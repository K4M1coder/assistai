# Experimental local voice components

These components are an early implementation, not the complete assistant. The React web UI is a separate mockup. The gateway serves its own experimental browser client, which has been exercised interactively; live interruption and echo handling remain incomplete.

## French speech recognition

`native_pcm.py`, `native_playback.py` and `native_turn.py` provide experimental PCM conversion, buffering and energy-based turn handling. `native_audio_client.py` connects them to default Windows WASAPI input and output. In one user-reported test it understood a spoken French question and manual interruption worked; an earlier physical smoke test did not recognize its synthetic question. It opens the microphone and speaker when run. Speaker-safe is the default; in an interactive terminal press `I` to interrupt playback, or `Q` to quit. `--aec` opts into the pinned, separately installed AEC comparator and enables voice barge-in. AEC mode interrupted its own playback in synthetic loopback tests and is not ready for reliable speaker use. A separate idealized replay showed that longer onset detection can miss near speech. Only loopback gateway URLs are accepted. AEC failure stops the client rather than passing raw microphone audio.

For research, `--speaker-enrollment path/to/voice.wav` enables CPU target-speaker extraction with an explicit 3–30 second mono 16 kHz PCM16 WAV, after installing the VoxLock experiment dependencies and models described in the noisy-room research notes. It cannot be combined with `--aec`; speaker-safe playback and manual interruption remain in effect. The client reads but does not delete the enrollment file. This option is unvalidated with physical voices and may clip speech or select an unintended speaker; it is not authentication. An immediate-onset synthetic-device test lost most of the question before a 200 ms internal silence warm-up was added; one test afterward transcribed it correctly. Do not infer robust noise suppression or automatic voice interruption from this experiment.

To record an enrollment sample explicitly on Windows, choose a quiet room and run the following from the repository root. Recording starts when the command says so; speak naturally for the requested duration. The file contains your voice and persists until you delete it yourself. Choose a different new path if it already exists. The command will not overwrite an existing file and does not check that the sample contains the intended speaker.

```powershell
.\.venv-voice\Scripts\python.exe -m prototype.enroll_speaker .cache/my-speaker-enrollment.wav --seconds 8
.\.venv-voice\Scripts\python.exe -m prototype.native_audio_client --speaker-enrollment .cache/my-speaker-enrollment.wav
```

The enrollment command accesses the default microphone only when run, buffers the recording in memory and writes the WAV after capture. A capture overflow aborts before writing; an interruption or disk error during writing may leave a partial file. The chosen gateway and other services have their own storage behavior.

On this research machine, with the cascade gateway running, the optional dependencies already reside in `.cache/pywebrtc-audio-research`. Run from the repository root in PowerShell:

```powershell
$env:PYTHONPATH="$((Get-Location).Path);$((Resolve-Path .cache/pywebrtc-audio-research).Path)"
.\.venv-voice\Scripts\python.exe -m prototype.native_audio_client
# Experimental AEC and voice interruption: append --aec
```

The opt-in AEC path requires `pywebrtc-audio` 0.2.0, `sounddevice` 0.5.3, and the inspected source under `.cache/hf-speech-research` at commit `ebc09bf286edbe8739a59575709070f056d31e29`; other required Python dependencies are in the research environment. Run the component tests with `.venv-voice/Scripts/python.exe -m unittest prototype.test_native_pcm prototype.test_native_playback prototype.test_native_turn prototype.test_native_audio_client`. `scripts/probe-native-client-fake.py` exercises the client with synthetic devices and the real local gateway; set `ASSISTAI_TEST_AEC=1` to exercise the AEC path. Neither test uses physical devices or establishes real-room echo performance, end-to-end flow control or noise resistance.

The native client also accepts `--vad silero` to combine the RMS gate with an experimental CPU speech classifier. It expects `silero-vad==6.2.3` installed under `.cache/silero-vad-research` and ONNX Runtime in the environment; the model digest is checked before loading. For this machine the research-only model can be installed with `.venv-voice/Scripts/python.exe -m pip install --no-deps --target .cache/silero-vad-research silero-vad==6.2.3`. Speech from a TV or another person can still activate it. It has only synthetic test coverage; it is not speaker recognition or a substitute for proven echo cancellation. Run `.venv-voice/Scripts/python.exe -m unittest prototype.test_silero_vad` for classifier state tests.

`scripts/probe-vad-asr-comparison.py` compares the energy and Silero gates with the existing local Vosk sidecar on synthetic mixtures. In one experiment, Silero avoided early triggering on white noise and harmonic tones, but did not improve white-noise word error or isolate the target from another synthetic voice. See EXP-083 for conditions and limits.

A separate low-volume physical WASAPI probe, `scripts/probe-wasapi-aec-live.py`, opened the default devices and retained aggregate microphone levels only. It did not run the gateway client or test live interruption; see EXP-077 before interpreting its measurements. Physical native-client synthetic-question tests at 0.5% and 2% thresholds failed to recognize the expected question (EXP-080). A later user-reported human-voice test succeeded once with manual interruption; no general recognition quality or automatic interruption reliability has been established.

For isolated gateway tests, set `ASSISTAI_DB_PATH=:memory:` before starting the gateway. Session events then live in a process-local SQLite database until the gateway exits; `/health` reports `history_storage: volatile`. This does not guarantee that the operating system or other services never write related data to disk. The physical client probe `scripts/probe-native-client-live.py` refuses to open devices unless the loopback gateway reports volatile history. A database from the earlier EXP-078 run remains in `.cache/physical-native-probe-20261111/events.sqlite` because automated deletion was blocked.

The Windows demonstration uses the repository's `.venv-voice` environment and `.cache/huggingface` model cache. Keep `HF_HUB_OFFLINE=1` for the existing Pocket TTS model; using the default cache path can make offline startup fail. The demonstration gateway uses port 18088. See the research log for the verified service configuration and its limits.

Create a Python 3.11 or 3.12 environment, install the pinned direct dependencies in `requirements.txt`, then run `python scripts/setup-vosk-fr.py` from the repository root. This downloads the public Vosk French small model into `.cache/vosk`. After setup, the recognizer runs locally without network access. Set `ASSISTAI_VOSK_MODEL` to use a different Vosk model directory.

From the repository root, start `python -m uvicorn prototype.asr_server:app --host 127.0.0.1 --port 18082`. `GET /health` reports readiness. The `/asr` WebSocket accepts binary mono 16 kHz little-endian PCM16 frames of at most one second. It emits JSON `partial` and `segment` events while audio arrives. Send `{"type":"end"}` to receive a `final` event and reset the recognizer, or `{"type":"reset"}` to discard the current utterance. Clients must collect `segment` events as well as the final text for longer utterances.

`python scripts/test-asr-sidecar.py path/to/mono.wav` resamples a 16-bit mono WAV and replays it at real-time speed. With no argument, it expects `.cache/french-test.wav`, produced by the Pocket TTS experiment. This is an integration probe, not a benchmark of real microphones, accents, noise, or word error rate.

## Limitations

The experimental browser client has been exercised with a live microphone, but sustained performance, accurate interruption and noisy-room behavior remain unverified. There is no authentication or enforced resource policy yet. Bind the sidecar to loopback and avoid exposing it to the network. Vosk's small French model is a baseline, not the final model choice; compare it against Kyutai STT and other candidates with an authorized corpus.

`gateway.mjs` is a separate experimental integration of the sidecar, a local OpenAI-compatible model server, and a local Pocket TTS server. It serves an experimental browser client at `http://127.0.0.1:18083/`, accepts text or PCM through `/voice`, and writes conversation events to `.cache/assistant/events.sqlite`. Optionally, `ASSISTAI_OPENCODE_URL` enables background delegation to a separately configured OpenCode server. Task completion is emitted as an event; the experimental browser queues a spoken notification when idle. OpenCode's own permissions apply: the gateway is **not** a sandbox. It must not be exposed to the network. Its short synthetic-audio test is `scripts/test-voice-gateway.py`; `scripts/test-gateway-delegation.mjs` exercises a read-only fixture. Neither test establishes live microphone performance or sustained hardware-budget compliance.

The client defaults to **speaker-safe mode**: it pauses microphone input while generated speech is playing to prevent acoustic feedback. Use the Interrupt button to stop the assistant and reopen the microphone. Uncheck the setting to experiment with automatic spoken interruptions; echo and false interruptions are not yet solved in that mode.

On Windows, `scripts/measure-windows-memory.ps1 -ModelPid <pid>` samples dedicated and shared GPU allocations, model process memory, available physical RAM and global page-file use. Establish a baseline before starting services and compare it with sustained audio, vision and agent workloads. This is monitoring, not an automatic memory limiter.

`resource-budget.mjs` contains an admission policy for dedicated GPU memory, shared-memory growth and system RAM reserves. An optional gateway check applies it before launching a background task. To enable it, provide `ASSISTAI_BUDGET_SAMPLE_PATH`, `ASSISTAI_BUDGET_BASELINE_SHARED_BYTES` (measured before model loading), and positive `ASSISTAI_TASK_VRAM_ESTIMATE_BYTES` and `ASSISTAI_TASK_RAM_ESTIMATE_BYTES`. `scripts/write-windows-budget-sample.ps1` can continuously publish snapshots for an explicitly selected Windows adapter. Missing, malformed or older-than-five-second samples reject task launches. This check is disabled by default; estimates are not reservations, and concurrent work, model loading, transient peaks, paging and hard limits are not controlled. The gateway currently uses a fixed 24 GiB budget with a 2 GiB reserve; this is unsuitable for adapters with less available memory. Shared-memory counters are warning signals, not proof of allocation origin. `notification-queue.mjs` serializes spoken notifications and defers them when interrupted; behavior under load needs validation.

When enabled, admission is serialized across connections within the gateway process and includes an estimate for each accepted task. Estimates are released after a confirmed terminal result; an ambiguous submission, status error or timeout keeps its estimate held until the gateway exits. This can reject legitimate later work, and the estimates can double-count memory already represented in the sample. Restarting loses the accounting even if an external task remains active; other gateway processes and non-gateway workloads are not coordinated. This does not reserve GPU memory or make a 24 GB limit enforceable.

Admission failures emit `task.rejected` for the client. The cascade path speaks a fixed explanation; the experimental native-speech model may still misdescribe the failure. The isolated real-model check is `scripts/probe-task-rejection.mjs` with `ASSISTAI_TEST_VOICE_URL` targeting a test gateway configured with a missing sample.

## Experimental LFM realtime gateway

Set `ASSISTAI_LFM_REALTIME_URL` to a loopback `/v1/realtime` WebSocket endpoint to opt into the LFM bridge; without it, the existing cascade remains the default. `ASSISTAI_LFM_WORKSPACE_CONTEXT` can provide a short explicit workspace description. This is an experimental developer path, not an automatic model launcher or enforced memory policy. The browser has not yet been tested live in this mode; text and image input are unavailable, and a spoken completion notification passed a synthetic real-model test, but has not been verified in a live browser. OpenCode retains its own permissions and is not an OS sandbox. See [EXP-054](../docs/research/2026-11-10-native-duplex.md#exp-054-opt-in-lfm-gateway-and-synthetic-interruption) for conditions and limits.

The gateway sends a `session.capabilities` event when the client connects. Native speech mode disables the text and image controls. Set `ASSISTAI_LFM_TRANSCRIPT_ASR_URL=ws://127.0.0.1:18082/asr` to opt into parallel CPU Vosk transcription; otherwise native input transcription is unavailable. It is a separate, potentially inaccurate recognition of the captured audio, not the model's internal interpretation. Final transcripts and assistant responses are saved to local session events. On an upstream reset, a bounded selection of recent events and task results is sent as explicitly untrusted context to the replacement session. This is not cross-connection memory or a prompt-injection boundary. Its connection and buffering are bounded and failures do not stop native speech. The synthetic real-Vosk adapter test is `node scripts/probe-native-transcript.mjs <16kHz-mono-PCM16-file>`. Native browser and real microphone behavior remain unverified.

When parallel transcription is configured, the gateway's service list reports its engine, model and health as `Parallel transcription`, distinct from the speech-to-speech model. It is omitted when not configured. Service health is a snapshot and does not establish which model actually produced a particular transcript.

The Windows native client's connection to the native gateway protocol can be exercised without physical audio devices using `node scripts/probe-native-client-mock-gateway.mjs` while the local Vosk sidecar is running. Set `ASSISTAI_TEST_MANUAL_INTERRUPT=1` for a separate simulated manual-interruption and late-audio test. It uses a mock realtime inference server, synthetic input and generated test PCM, and volatile gateway history; it does not demonstrate real-model speech quality or native inference. The client prints the gateway-reported mode on connection.

Native completion notifications pass a bounded excerpt of the completed task result to the speech model, with tools disabled for that response. The full result appears in the client. The generated summary is not guaranteed accurate and untrusted result text is not isolated from the model.

After a native reset, a completed exact normalized task is reused within the current connection unless the model explicitly sets the `rerun` tool flag. This prevented the observed duplicate in one real-model synthetic test, but different wording, a model-selected rerun, reconnection or cache eviction can still repeat actions; reuse can also return stale results. The model's decision to set `rerun` is not independently verified against the user's speech. The regression probe is `scripts/probe-lfm-reset-context.mjs` and requires synthetic fixture files and the isolated native trial described in the research notebook.
