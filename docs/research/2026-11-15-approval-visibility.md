Saying confirmation did not approve the task. This is a real user report; the earlier fixture task was not tested in that exchange. The running OpenCode fixture is explicitly configured for read, glob and grep only: it does not provide web search or editing, and approval does not enable them.

The source had an approval section above the conversation and a French spoken acknowledgement that requested confirmation without explaining the button requirement. One plausible cause is that the section was outside the visible scrolled viewport; that is an inference, not a verified observation. Attempts to inspect the user's VS Code window with the computer-use helper failed because its native pipe was unavailable. The browser access host was also unavailable. The exact state of the user's page and the reason the button was not seen were therefore not established.

The approval panel now appears as a fixed, high-contrast viewport overlay when a proposal arrives, with text explaining that spoken confirmation does not submit approval. The gateway's French acknowledgement explicitly directs the user to the Approve task or Decline task button. A rejection without the current approval ID no longer hides an unrelated pending proposal. These changes preserve explicit, single-use task approval; they do not implement voice authorization.
