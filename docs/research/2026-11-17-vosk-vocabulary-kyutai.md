# Filename vocabulary and Kyutai STT candidate — 2026-11-17

## Hypothesis and exact vocabulary check

The observed errors for `fixture.txt` and `calculator.py` may reflect vocabulary coverage, not merely acoustic noise. The local Vosk Python API exposes an exact word lookup. Running `.venv-voice/Scripts/python.exe scripts/probe-vosk-vocabulary.py` against the installed `vosk-model-small-fr-0.22` found no exact entries for lowercase `fixture` or `calculator`; `calculateur`, `py`, `texte`, `fichier`, `addition`, `soustraction` and `pas` were present. The local model was loaded on CPU in a short-lived process; no speech was processed in this check. Exact absence does not prove every spelling or phonetic route must fail, nor does a word being present guarantee recognition.

Vosk's [runtime vocabulary adaptation documentation](https://github.com/alphacep/vosk-space/blob/master/adaptation.md) describes dynamic graphs and grammar changes, while an [upstream issue](https://github.com/alphacep/vosk-api/issues/1314) shows that out-of-vocabulary grammar words are ignored. Therefore adding these exact absent words to a runtime phrase list alone is not a demonstrated solution. A restricted grammar can distort open conversation, negation or file names. We do not silently substitute a similarly pronounced filename; transcript review and explicit task approval remain necessary.

## Candidate and setup

Kyutai's [original model card](https://huggingface.co/kyutai/stt-1b-en_fr) describes English/French streaming STT with a 0.5-second model delay and CC-BY-4.0 weights. This is an author claim, not an end-to-end latency measurement on the B60. The [CrispASR GGUF conversion card](https://huggingface.co/cstr/kyutai-stt-1b-GGUF) describes a Q4 variant for its runtime; its page metadata says CC-BY-4.0 while its prose also says MIT. Treat the original weight license and conversion provenance as separate items requiring review before distribution. The locally installed CrispASR 0.8.53 CPU build lists `kyutai-stt` as a backend; this does not prove compatibility, speed, streaming support or accurate French filenames.

`scripts/setup-kyutai-crisp-model.py` downloaded only `kyutai-stt-1b-q4_k.gguf` at revision `ab83b1b3c788a8842e5ce5deebc6f6491545ead8` to ignored local cache. Its 666,565,184 bytes matched publisher SHA-256 `32937b2c337e8b8b1bfd68bc90f07a1dbc9fcdfd5e7099dc770e15f0cbff512e`. The verified download does not itself establish trust, quality or compatibility. Model weights are not committed. Re-running verifies an existing file and refuses an unexpected one.

## Guarded comparison and trailing-silence hypothesis

The guard subsequently passed and three guarded experiments ran with the downloaded Q4 file in CrispASR 0.8.53 CPU mode. Synthetic French Pocket TTS audio was sent to Vosk and the candidate; the candidate was loaded afresh for every file. The first filename-only run returned `fix` where the reference contained `fixture point texte`, and `nice me fichait` for a spelled name. This suggested a possible unfinished delayed stream, but did not establish its cause.

The probe gained `-ComparePadding` to send each identical synthetic waveform to the candidate twice, once unchanged and once with 1,000 ms of trailing silence. For the same filename audio, the candidate changed from `... fichier fix` to `... fichier fixturetxt`. For the spelled phrase it changed from `ni le fichier fxt` to `ni le fichier fxt repointerxt`. This shows additional text was emitted in these two cases, not an exact filename or proof that the only cause was delayed decoding. The comparison's Vosk output used the unpadded audio. It did not open physical devices or execute tasks; its temporary synthetic files were deleted on normal completion.

The second padded comparison used three other French coding phrases. Vosk and Kyutai both retained the addition/subtraction order and negation markers. Kyutai with padding recognized the end of the negation phrase (`contenu`) that was missing without padding, but both Kyutai variants omitted the initial `Corrige` in the operation phrase. For `calculator point py`, Vosk said `calculateur pont qui`; Kyutai with padding said `calculatorpi`, followed by the rest of the request. Neither produced the exact `calculator.py` path. The two recognizers are not interchangeable based on these cases, and an application must not infer or silently substitute a filename.

For the initial filename comparison, 16 whole-system samples recorded peak dedicated 12,344,774,656 bytes, peak shared 258,867,200 bytes and minimum available RAM 10,674,417,664 bytes. The paired padding comparison recorded 19 samples with peak dedicated 12,197,191,680 bytes, peak shared 265,420,800 bytes and minimum RAM 10,680,754,176 bytes. The three-case comparison recorded 30 samples with peak dedicated 12,196,368,384 bytes, peak shared 263,323,648 bytes and minimum RAM 9,871,781,888 bytes. These samples cannot exclude brief peaks, paging or allocations outside VRAM; all used the same 256 MiB shared stop signal and completed without it triggering. Logs are under `.cache/asr-coding-20261117-191200-006.*`, `-191257-720.*` and `-191333-757.*`.

Candidate file-mode times including model loading were roughly 2.3–2.9 seconds without the added silence and 2.8–3.5 seconds with it; Vosk timings included real-time-paced input to an already loaded service. These figures are not a fair latency comparison or a streaming benchmark. These five utterances share one synthetic voice and are not a human or noisy-room corpus. This CPU research runtime's native Kyutai streaming support and real-time performance are not established; do not replace the live recognizer based on this result. A next experiment should evaluate an implementation with verified stream flush and a broader, consented speech corpus while measuring complete resource use.

## Full coding request comparison — 2026-11-22

Following a failed real-agent edit with incorrect identifiers, `powershell -NoProfile -File scripts/run-asr-coding-probe.ps1 -EditCase -CompareCrisp -Kyutai -ComparePadding` sent a freshly synthesized version of the complete coding request to Vosk and the Q4 CPU Kyutai candidate. Both candidate variants received the same PCM; the second added one second of silence. Vosk returned `calculateur point pis` and `http` in place of `calculator point py` and `add`. Both Kyutai variants returned `calculatorp` and retained `add`; adding silence did not alter this result. Both retained the words for addition and subtraction, but neither recovered every diagnostic identifier as separate tokens. Kyutai's normalized WER of 0.292 versus Vosk's 0.167 also reflects punctuation and word segmentation, and cannot by itself rank semantic quality. Candidate processing took 4,578 / 4,766 ms including model load; Vosk's 7,328 ms included paced input. These are not matched latency measurements.

Nineteen system samples (`.cache/asr-coding-20261122-024918-513.*`) peaked at 11,433,992,192 dedicated GPU bytes and 179,703,808 shared, with minimum available RAM 8,941,289,472 bytes. Neither a physical microphone nor a task agent was used; the synthetic audio and temporary candidate files were deleted. The identical waveform within this comparison makes the identifier contrast informative, but one generated voice cannot establish a population error rate. The candidate remains CPU-resident, and neither this test nor sampled counters satisfy the strict all-models-in-VRAM requirement. Further work must address exact identifiers without assuming a phonetic guess is correct.
