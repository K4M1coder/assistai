# Opt-in web research fixture — 2026-11-17

## Hypothesis and sources

The local agent may be able to perform the operator's requested Internet research without loading a new GPU model. This requires network access for search and source retrieval even though model inference remains local. The installed OpenCode reports 1.19.5. Its [V1 tool documentation](https://opencode.ai/v1/docs/tools/) says `websearch` requires an enabled provider such as `OPENCODE_ENABLE_EXA`, sends searches to a hosted service, and `webfetch` retrieves pages. Documentation of the current V2 is not proof of behavior in this binary. This option cannot satisfy a literal offline-only search requirement and should not be represented as a local search engine.

## Isolated configuration and checks

`scripts/setup_opencode_web.py` created a disposable `.cache/agent-web-demo` configuration, refusing to overwrite a pre-existing directory. It allows `websearch` and `webfetch`, denies `external_directory` and unspecified tools, and points to the existing local Gemma server. OpenCode permissions are application-level and not an OS sandbox; gateway and harness are unauthenticated loopback services. `scripts/start-windows-harness.ps1 -WebFixture` sets `OPENCODE_ENABLE_EXA=1` for the spawned harness and removes the competing provider flag, restoring the parent environment afterward. The gateway on port 18121 displays that search queries go to hosted Exa and page requests to their websites, including inside the explicit task-approval panel. The label is not a data-loss prevention mechanism; a generated query might include sensitive content.

The first startup failed because an environment flag was set to an empty string, which the installed runtime rejected. The launcher now removes absent flags rather than setting empty values, and the second startup succeeded. The `/config` endpoint showed the intended provider and permission configuration. `/experimental/tool/ids` and the local-provider tool-schema endpoint included `websearch`; tool enumeration alone does not prove permission enforcement, network reachability, search execution, source quality or actual tool calling. The installed model, Vosk and Pocket TTS endpoints also reported available. No new model was loaded and no search was executed at this checkpoint.

At gateway startup the sampled whole-system dedicated GPU use was 11,574,587,392 bytes, shared GPU use 197,799,936 bytes and available RAM 15,641,321,472 bytes. The check is advisory, not a continuous hardware limit or no-spill proof. Two Python fixture tests and four JavaScript approval/client tests passed; these use temporary fixtures and mock gateway components and do not validate live search. A human-reviewed, approved public search and inspection of returned source links are still required. The read-only and editing fixtures remain separate and were not restarted.

`node scripts/probe-web-proposal.mjs` then sent a synthetic typed request concerning Nantes's official website through the real controller and this gateway. The proposal preserved the official-site and source-link intent by inspection; the capability event disclosed hosted Exa. The probe explicitly declined the proposal and observed 458,880 audio bytes. It did not hear the output or perform an Internet search. A correct proposal does not establish successful search or source attribution.

`node scripts/probe-web-research.mjs` prepares an operator-attended live check against the web fixture. It states the external-network destination, prints the original and proposed task and accepts approval only from an interactive terminal after explicit `y`. It requests a spoken notification after completion and reports returned URL strings and audio-byte counts; the URLs still need independent source verification and the audio must be heard to assess intelligibility. A mock gateway test verified that the probe declines when no interactive terminal is available. No live search was executed in this preparation, and an approved run is still required. A timeout or uncertain task is not proof of termination.

## Direct public-page test, 2026-11-19

The operator subsequently requested direct delegation without task-approval gates. With the existing local LFM3 text controller, Gemma agent, Vosk and Pocket TTS services, `powershell -NoProfile -File scripts/start-windows-harness.ps1 -WebFixture` and `powershell -NoProfile -File scripts/start-windows-demo.ps1 -WebFixture -Port 18121 -CancelOnPressure` started a separate web fixture and temporary gateway. `node scripts/probe-web-direct.mjs` sent a synthetic text request directly through the gateway and queried the resulting OpenCode tool records. No new GPU model or physical microphone was used. The fixture allows hosted Exa search and direct website retrieval; Internet destinations are external even though inference and agent execution are local. Its permissions are not an OS sandbox.

The first request targeted `https://www.nantes.fr/`. The agent attempted `webfetch` twice, both tool records had error status, and the final text reported a transport error. A separate Windows HTTPS request also failed with TLS alert 112. The agent's error notification contained 393,600 audio bytes, but was not listened to or transcribed. This failed request does not prove that all web retrieval is broken. An independent inspection found the current [Nantes municipal and metropolitan website](https://metropole.nantes.fr/); a local Windows request returned HTTP 200 for that address.

`node scripts/probe-web-direct.mjs --official` then directly delegated a request to fetch `https://metropole.nantes.fr/`. OpenCode recorded a completed `webfetch` to that URL, with the official title in the returned content. The agent's final text returned the same title, `Bienvenue sur le site de Nantes, ville et métropole | Nantes, ville et métropole`, and the URL; that title was independently checked on the official site. Its notification contained 455,040 audio bytes but was not heard or independently transcribed. This verifies one public-page retrieval and a correct text result, not general Internet search, hosted Exa behavior, news coverage, citation accuracy across other pages, automatic vocal input or notification intelligibility. The probe now reports all tool names and checks the returned URL; that extra reporting was added after these two runs and has syntax coverage only.

Gateway startup observed 11,060,862,976 dedicated GPU bytes, 138,752,000 shared and 15,143,280,640 available RAM. A later snapshot during the second task showed 11,059,662,848 dedicated, 167,571,456 shared and 15,411,437,568 available RAM. These are snapshots, not peaks or proof of a hard 24 GB limit or no spill. The gateway's optional pressure cancellation was enabled; no pressure cancellation was observed. After the harness reported no busy sessions, both temporary services were stopped through their ownership records; the main demo remained running. A timeout in this probe must not be treated as task termination.
