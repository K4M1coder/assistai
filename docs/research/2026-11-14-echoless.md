# EXP-191: System-reference echo cancellation candidate

[Echoless v1.2.0](https://github.com/Haor/Echoless/tree/0b7a77cf152af0b545cdeb16849ec812c2511418) is a candidate for the unresolved speaker echo problem. Its documentation describes Windows WASAPI loopback reference capture, a delay probe, a Rust AEC3 implementation and optional CPU LocalVQE. It describes Windows virtual-microphone output using VB-CABLE; its Linux support is marked experimental. Those are upstream claims, not tests on this machine. The project source is MIT-licensed and includes separately licensed components; review the bundled third-party notices and any virtual-device license before redistribution.

The official 15,245,510-byte Windows v1.2.0 ZIP was downloaded to the research cache and matched published SHA-256 `df9445ddddd8d52beee1513fb45f3fca584842f61c75d0ab4c435c154736a416`. `scripts/inspect-echoless-release.py` verifies and lists the archive without extracting or executing it. The executable was subsequently extracted and run only for an [offline synthetic comparison](2026-11-14-echoless-offline.md); no app, model or virtual driver was installed and no audio device was opened.

The pinned [`probe_delay.rs`](https://github.com/Haor/Echoless/blob/0b7a77cf152af0b545cdeb16849ec812c2511418/crates/echoless-cli/src/probe_delay.rs) analyzes `mic.wav` and `ref.wav` from a diagnostic session and attempts to remove the session unless retention is requested. Thus a physical calibration can write microphone and system-audio recordings temporarily, and cleanup can fail; it is not suitable as a privacy-preserving in-memory test without further work. No such recording or calibration was made here. Its claimed delay measurement is not a guarantee for this user's speaker, room, drift or overlapping speech.

The browser client now offers an input-device selector to support a future virtual microphone or a different physical input. It does not install or enable Echoless, and changing selection requires restarting microphone capture. Mock tests and a [synthetic Chrome fake-device test](2026-11-14-microphone-selector-browser.md) verify enumeration and a capture restart with the selected ID; real virtual-device routing, echo cancellation, interruption, latency and resource use remain unverified. Speaker-safe remains the known conservative option.
