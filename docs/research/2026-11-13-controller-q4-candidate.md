# EXP-174: Smaller controller checkpoint preparation

The running cascade controller uses the official LFM3-1.7B Q8_0 GGUF. Its local 1,846,238,496-byte file matched publisher SHA-256 `8f6b24182258205e9e01e21f1f24a1f208c1e8115578825d202ce39976af20b6`. The [publisher's pinned GGUF repository](https://huggingface.co/LiquidAI/LFM3-1.7B-GGUF/tree/cd0c74c575b5c416f3011b5b4c298077f26ca8c2) lists a Q4_K_M file of 1,099,627,808 bytes. `scripts/setup-lfm3-controller-q4.py` downloaded that exact revision to the research cache and verified size and SHA-256 `3793e1e6e2266919d6e015287221b41100175a98eddaba92e111aed3b05c93c4`.

The on-disk difference is 746,610,688 bytes, approximately 712 MiB; it is not a measured VRAM, RAM or latency saving. The model card also lists a separate QAD Q4_0 checkpoint; it is a different quantization-aware variant and was not downloaded or tested here. The [model's own card](https://huggingface.co/LiquidAI/LFM3-1.7B) describes it as a tool-calling model and cautions against relying on it for complex coding or multistep reasoning. The LFM Open License applies; review its terms before redistribution.

No model was loaded for this preparation and the running demo was not changed. Before selecting Q4, compare both checkpoints on French delegation, preservation of operation direction and negation, tool argument correctness, conversation and cancellation, latency, and measured system resources using an isolated, guarded configuration. The available shared-GPU headroom is too small to justify loading a second model alongside the current stack; changing the active controller would also affect existing users. Neither Q4 quality nor the simultaneous 24 GB no-spill constraint is established.
