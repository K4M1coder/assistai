# EXP-176: Cooperative admission across gateway processes

Previously each gateway maintained only its own active task estimates, allowing two gateways using the same GPU to admit independently. An optional SQLite ledger now serializes a fresh-sample budget check and insertion in one immediate transaction. It sums each participating reservation's own RAM and VRAM estimates. Windows demo starts configure a shared path; resource status labels it `participating-gateways`, not global enforcement.

Tests passed with two independent database connections and two separate Node processes competing for capacity. An orphaned reservation survived reopening, so crashes or uncertain submissions do not silently release estimated capacity. A failed or locked ledger rejects admission. Reconciliation must follow independent verification that the corresponding task is no longer running; deleting a reservation can otherwise permit oversubscription. Existing gateway processes, direct service users and any gateway with another path remain uncoordinated. Samples can age and allocations are not reserved; GPU spill or system paging can still occur. No GPU model or physical audio was used in these tests.
