# EXP-179: Sparse agent virtual-page snapshot

The read-only Windows diagnostic queried the idle agent process without reading memory contents. Windows reported 13,772,087,296 bytes in committed private regions; a separate process snapshot reported an 11,558,912-byte working set and 13,822,300,160 bytes private commit. In the six largest approximately 1.0–1.07 GB allocations, every sampled page at a 1 MiB stride returned a valid flag. In a roughly 826 MB allocation, none of 788 sampled pages returned that flag. The valid samples in the ten largest allocations reported zero `Shared`, `Locked` and `LargePage` bits. These are sparse flags, not counts of all pages or a model-tensor inventory.

[Microsoft documents](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-queryworkingsetex) that `QueryWorkingSetEx` can query addresses outside the ordinary process working set, and the [flag definition](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-psapi_working_set_ex_block) says `Valid` determines whether other fields can be interpreted. Therefore, the flags cannot be extrapolated to resident CPU RAM, GPU VRAM or disk-backed model bytes, and they do not resolve the apparent mismatch with the small working-set counter. This is not proof of no spill or of which pages belong to model tensors. GPU-driver mappings, aliasing and sampling bias remain unresolved.

The diagnostic now reports shared, locked and large-page flags only for valid sampled pages, and its output explicitly states the limitation. No process contents, model inference or physical audio were used. A Windows self-inspection test checks count bounds; the existing service was not restarted.
