# EXP-200: Native speech backend disconnect recovery

The native bridge could leave its client connection open after the underlying realtime session unexpectedly closed. That left the browser with no functioning native speech session and no connection-level signal to invoke its existing reconnect behavior. Backend faults were reported, but the same dead session could remain attached.

When the active native backend now closes, the bridge stops the optional transcript sidecar, reports an unexpected close if no fault was already reported, and closes the client WebSocket with code 1011. The browser's existing connection handling can then reconnect. Intentional replacement for an interrupted or reset session sets the old session aside before closing it, so it does not close the client. An output-backpressure fault is reported once before closure.

Mock native bridge tests cover an unexpected close, a fault followed by closure, and intentional session replacement. The realtime session and native gateway mock integrations also passed: 17 tests in total. No real backend disconnect, physical microphone or audible recovery was tested. A native terminal client may exit on disconnection rather than reconnect automatically; this change does not assert otherwise. Running gateways must restart to acquire it. This is not evidence of full-duplex speech or a memory guarantee.

An additional integration starts the actual gateway in a separate process with volatile history and connects it over loopback WebSockets to a simulated realtime backend. After the backend handshake, the test closes that backend socket and observes the client receive the error and close code 1011. This verifies the transport boundary, not reconnection to a real model or recovery of an interrupted utterance. That integration and the bridge tests passed 11 tests together; no model, physical device or existing gateway was disturbed.

The optional parallel ASR sidecar could also throw synchronously if its socket failed while sending buffered audio, live audio or the end marker. Those sends now report `transcript.unavailable` and stop the affected sidecar session instead of letting the exception escape. Tests inject a synchronous send exception in each path; the native disconnect integration and sidecar tests passed five tests. This does not cover every asynchronous network failure or prove native transcript accuracy.
