# LFM3 Omni OpenVINO INT4 candidate — 2026-11-22

## Hypothesis and sources

The [OpenVINO conversion card](https://huggingface.co/OpenVINO/LFM3-Omni-2B-int4-ov) describes LFM3 Omni with INT4 language-model weights and default INT8 compression for embeddings, vision and audio components, with possible higher-precision residual weights. This is weight-only compression, not proof of quantized KV cache or all-VRAM placement. The card reports CPU functional checks for text, image, ASR and speech, but explicitly says GPU and NPU execution were not validated. Its examples use batch-style `OmniPipeline` calls, not a demonstrated realtime WebSocket or interruption mechanism. Speech requires SDPA, with paged attention unsupported for the cited build. The upstream [model card](https://huggingface.co/LiquidAI/LFM3-Omni-2B) lists French speech and the LFM Open License v1.0; the license and restrictions must be reviewed before distribution. These are publisher claims, not local performance results.

This route may improve Intel GPU support versus the tested GGUF/Vulkan path, but GPU support for every submodel, streaming, tool calls, latency, French output quality and concurrent 24 GB operation are unverified. The existing native GGUF route has already performed narrow synthetic voice and tool-call trials; neither candidate has demonstrated the requested complete system.

## Setup and local evidence

The publisher's Python 3.12 and 2027.0.0.dev20261119 OpenVINO, tokenizers and GenAI nightly stack was installed in ignored `.cache/lfm3-openvino-research-py312`, with NumPy 2.5.4 and Hugging Face Hub 1.33.0. A first Python 3.11 dry run failed because NumPy 2.5.4 requires Python 3.12; stale Windows launcher registrations for 3.12 did not point to existing executables. A valid locally installed Python 3.12.9 was used instead. `scripts/probe-openvino-omni-environment.py`, run after checking a fresh resource snapshot, detected `CPU` and `GPU: Intel(R) Arc(TM) Pro B60 Graphics (dGPU)` and the `OmniPipeline` API. This enumerated devices only; no model or inference was run, and device enumeration does not prove model compatibility or placement.

With an existing Python 3.12 executable, create the ignored environment with `python -m venv .cache/lfm3-openvino-research-py312`, then use its Python executable to run `-m pip install --pre --extra-index-url https://storage.openvinotoolkit.org/simple/wheels/nightly openvino==2027.0.0.dev20261119 openvino-tokenizers==2027.0.0.0.dev20261119 openvino-genai==2027.0.0.0.dev20261119 huggingface-hub==1.33.0 numpy==2.5.4 soundfile==0.14.0`. Transitive package versions are not locked, and availability of nightly wheels may change. This setup has not been reproduced from a clean machine.

`scripts/setup-openvino-omni-research.py` downloaded revision `7143e4693ca68ffe39e21613aed54f9c49a65ea6` into ignored `.cache/lfm3-omni-openvino-int4`: 45 files, 1,975,442,765 bytes. `--verify-existing` checked all sizes, 11 published LFS SHA-256 hashes and 34 Git blob hashes against that revision's Hub metadata. Weights and environments are not committed. Downloading verifies a particular snapshot, not runtime safety or quality.

## Targeted next experiment

`powershell -NoProfile -File scripts/run-openvino-omni-probe.ps1` requests GPU pipeline initialization under the same 10 GiB available RAM, 18 GiB dedicated and 128 MiB shared preflight limits used for other native trials; runtime checks stop its owned process tree at 6 GiB available RAM, 22 GiB dedicated or 256 MiB shared. `-Infer` additionally attempts a pinned synthetic French WAV and generated interleaved speech, saved in ignored cache for independent analysis; it is prepared but not tested. On November 22, `-PreflightOnly` rejected startup at 205,459,456 shared GPU bytes, with 11,288,174,592 bytes available RAM and 11,256,238,080 dedicated GPU bytes. No pipeline, model or inference was started. When headroom returns, test initialization first, inspect all process and adapter telemetry, then attempt the bounded file-audio case and independently assess speech. A successful GPU request still would not prove all components reside in VRAM, no transients or paging, realtime throughput, tool calling or barge-in. Do not raise the guard to force a pass.

The installed GenAI 2027 nightly's Python API documentation exposes `speech_streamer`, which emits 24 kHz audio chunks and can return `RUNNING`, `STOP` or `CANCEL`. Its documentation describes LFM3 chunk overlap and configurable left context; this is an API contract, not measured simultaneous input/output. The prepared probe now supports `-Infer -Stream` and `-Infer -Stream -StopAfterFirst`, retaining bounded chunks and reporting first-chunk time. Two tests with fake tensors and the installed API verified callback copying, size/finite checks and requested stop status; they did not load or run a model. A later preflight still rejected 209,588,224 shared GPU bytes. Chunk delivery, cancellation, timing, audio quality and interaction with concurrent user speech remain untested on B60.

The experimental callback now serializes external stop requests with chunk capture and discards any subsequent callbacks instead of appending late audio. Three component tests use real OpenVINO tensor objects and a separate thread for the stop request; the model itself is not involved. This is not yet connected to the browser, does not clear already scheduled speaker audio, and cannot guarantee the runtime stops promptly or that no callback raced before the stop request. On November 22, another GPU preflight rejected 178,589,696 shared bytes; no model inference was performed.

The installed `ChatHistory` API accepts tool definitions, and `scripts/probe-openvino-tool-template.py` loads the local tokenizer and renders a synthetic history containing a `delegate_task` definition, a call with mapping arguments, and a `BLUEBIRD` tool result. All four markers were present in the rendered prompt. A JSON-string argument was also preserved with GenAI's default template polyfills, but the same input was rejected when `apply_polyfills=False`; the underlying pinned template requires a mapping. The test did not load inference weights, generate a tool call or run a tool. It identifies an adapter requirement and a potential mismatch with OpenAI-style serialized arguments, not proof that a realtime agent bridge works. A later guarded GPU preflight again rejected 209,588,224 shared bytes, so model behavior remains unmeasured.

The upstream [LFM3 model card](https://huggingface.co/LiquidAI/LFM3-Omni-2B) describes a tagged function/parameter representation and application-side tool dispatch. `prototype/openvino_tool_calls.py` is a separate experimental parser for completed responses containing only `delegate_task(task)`: it bounds message length, task length and call count, preserves call order, and rejects malformed, nested or unsupported tagged blocks. Four unit tests use constructed strings; no model output, tool execution, streaming parsing, agent connection or real-world robustness has been validated. The parser is not wired into the live gateway and does not by itself provide permissions, cancellation or session semantics. Before integration, compare actual generated outputs and failure modes against the model's published format, including multi-call and truncated-stream cases.

On November 22, the template probe was extended to extract the synthetic assistant call from the actual locally rendered template and pass it to the experimental parser. It returned the expected function and task; a unit test also checks that selected truncated tool-marker prefixes are rejected. This is a tokenizer/template round trip using constructed history, not model-generated output or proof that every truncation or adversarial case is handled. GPU initialization was again refused by preflight at 196,153,344 shared bytes, so no model inference was attempted.
