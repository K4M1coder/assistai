# EXP-162: OpenCode task completion markers

Inspection of the local read-only OpenCode service's recent assistant message metadata found completed steps with `stop`, `tool-calls`, and `length` finish reasons. No message contents were recorded. A completed model step is therefore not necessarily a completed task. The [upstream session processor](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts) separately records completion and finish information; an [upstream report](https://github.com/anomalyco/opencode/issues/40146) describes output-limit truncation being stored as `length` without an error. That report is context, not proof of the behavior of every OpenCode release.

The gateway now waits if its latest completed assistant message has `tool-calls`, an unknown finish, or no finish; it reports `length` as a task error rather than a successful result. An explicit error is also reported as an error. A mock integration test supplies a completed tool-call step before the final answer and verifies the gateway waits. Unit and integration tests passed; the currently running demo predates this change. This does not prove that a `stop` response completed the user's intended work, and an uncertain task can still remain pending until timeout.
