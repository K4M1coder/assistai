# EXP-199: Review of an alternative LFM3-Audio runtime

Hypothesis: a different native C++ runtime could provide better French real-time speech-to-speech and agent control on the B60 without loading a second copy of the model. This review does not demonstrate that hypothesis.

The [model publisher](https://huggingface.co/LiquidAI/LFM3-Audio-2B) distinguishes multilingual transcription and synthesis from voice chat, which it currently describes as English-only. Its model card separately describes tool calling. Small French trials in EXP-049 are observations outside that stated chat support, not proof of reliable French conversation.

[audio.cpp at revision `d38518a0d6a7aaab9d3f3dd91e9780c69857b0ac`](https://github.com/0xShug0/audio.cpp/blob/d38518a0d6a7aaab9d3f3dd91e9780c69857b0ac/docs/models/lfm3_audio.md) documents experimental LFM3-Audio speech-to-speech and Windows/Linux Vulkan builds. Its documented live path accumulates the question and begins encoding and generating after input ends; its live HTTP request is described as a first turn. Its conversation mechanism sends prior audio and acoustic-token artifacts again. These are project claims, not measurements on this machine, nor evidence of full-duplex interaction. The documentation says its ASR task does not support typed instructions or tool calls; it does not establish that its S2S interface exposes the structured tool protocol needed by this project. Its S2S interface accepts automatic language selection, not an explicit French voice-chat mode.

The same documentation limits prompt plus output to 8,192 steps and reports reduced accuracy with Q4 backbones on its own examples, recommending Q8 or better. That finding is specific to its measured cases, not proof that a particular local Q4 task will fail. Q8 may also change the memory tradeoff and needs a complete runtime measurement. Generic Vulkan package availability is not proof of B60 compatibility, speed, quantized KV support or no spill.

Decision: retain this as a candidate for a future isolated benchmark, not a replacement for the existing native llama.cpp bridge. First verify a pinned Windows Vulkan build, model/projector compatibility, structured tools and multi-turn behavior. Measure simultaneous dedicated and shared GPU memory, RAM and latency; test French intelligibility and interruption with consented physical audio. No binary was downloaded or executed and no model was loaded for this review. Existing demo connections were active, so no competing real-model benchmark was started.
