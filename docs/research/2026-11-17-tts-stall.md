# Cascade speech stream stall — 2026-11-17

## Observation and hypothesis

The operator previously reported cut-off or unintelligible speech. There is no evidence yet that an HTTP stall caused those reports. The installed Pocket TTS service streams a WAV whose data-length header is a placeholder. A fresh request for synthetic `Bonjour.` returned 59,564 bytes with a declared 2,000,000,000-byte data length. Thus the header cannot distinguish an ordinary stream end from a clean but premature end. Inspection of the installed service also showed a worker thread and queue feeding the streaming response; a stalled worker can leave the gateway waiting indefinitely. These observations do not establish why any user's audio was cut off.

## Change and test

The cascade gateway now bounds TTS inactivity to 15 seconds by default, covering initial HTTP response and gaps between chunks. A configurable `ASSISTAI_TTS_STALL_MS` accepts 100–120000 ms; excessively short settings may interrupt slow legitimate synthesis. On timeout, the current TTS request is aborted and a turn-specific error says audio may be incomplete; no successful `speech.end` is emitted. Explicit cancellation remains separate.

`node --test prototype/session-resume.integration.test.mjs prototype/task-notification.test.mjs prototype/client-mode.test.mjs` passed seven tests on Node v24.14.1. The integration test used mock LLM, ASR and TTS servers; its TTS sent a valid header and audio and then stopped producing bytes. The gateway reported the stall without `speech.end` and accepted the following successful turn. This is a simulated transport failure, not a physical microphone, audible playback, real Pocket TTS stall or proof that ordinary truncated streams are detected. Existing gateways were not restarted.

## Current-source real-service smoke check

`scripts/run-notification-transcription.ps1 -Marker rouge -Markup` launched a temporary current-source gateway and used the existing Pocket TTS and Vosk services with a synthetic task completion in a temporary database. The run returned 312,960 bytes of 24 kHz audio; Vosk's transcript contained `rouge` and the spoken code-display cue. This checked normal output through the updated gateway and existing real services, not the 15-second failure path, an actual agent task, physical playback or independently verified intelligibility. The temporary gateway stopped; existing services stayed running. Six whole-system samples recorded 12,132,093,952 bytes peak dedicated GPU, 239,976,448 bytes peak shared GPU, and 12,802,711,552 bytes minimum available RAM. Sampling does not rule out transients or spill; logs are local under `.cache/notification-transcription-20261116-233829-186.*`.
