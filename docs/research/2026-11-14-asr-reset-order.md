# EXP-196: Discard late recognition segments after reset

Hypothesis: when capture is reset, a recognition segment already being processed may reach the gateway after it clears its local segment list. If retained, that old segment could be prepended to a later utterance and affect the controller's proposed task.

The local Vosk server processes incoming audio and control messages sequentially and sends a `reset` acknowledgement only after replacing the recognizer. WebSocket message ordering therefore places a segment produced from preceding audio before that acknowledgement. The gateway now clears accumulated segments on the acknowledgement as well as when requesting reset. This relies on the current recognizer's ordered acknowledgement contract; it does not prove compatibility with an ASR service that omits or reorders acknowledgements.

The mock spoken-image integration sends an old segment after the gateway's reset request but before the reset acknowledgement, followed by a new final result. It verifies that the review contains only the new question and that the edited review reaches the vision request. The associated integration and session-resume tests passed. This is not a physical interruption test, an ASR accuracy measurement, or a general guarantee against transcript errors. The current running gateway must be restarted to acquire the change.

## Existing Vosk service protocol check

On this machine, `node scripts/probe-vosk-reset.mjs` connected twice to the existing loopback Vosk service using the existing synthetic French WAV. One connection sent the phrase once; the other sent it, requested reset, then sent the same phrase again. The latter returned exactly one reset acknowledgement before its final result, and the post-reset transcript matched the clean baseline (69 characters; SHA-256 `d2ae7a6ff579819e285c89edf536198cfadd300e88e8d8a11c70d972769ae5d4`). The probe did not print or persist the transcript. This checks the service's ordering and reset behavior for one synthetic input; it did not force a late segment at the gateway, assess transcription correctness, use a microphone or load another GPU model. Existing user sessions were left running. The separate mock test supplies the late-segment timing.

`node scripts/probe-gateway-asr-reset.mjs` then started the current gateway source on a temporary loopback port with volatile history and connected it to that same running Vosk service. It sent the synthetic phrase, a reset and the phrase again, with transcript review enabled. The gateway reported the reset acknowledgement and produced a 69-character review with the same hash as the clean direct-service baseline. The probe terminated its own gateway afterward. It did not submit the review, call the LLM, TTS or agent, capture physical audio, or force the race; it does not establish conversational or coding accuracy.
